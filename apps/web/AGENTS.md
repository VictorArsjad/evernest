# AGENTS.md — `apps/web` (Vite + React PWA)

Scoped notes for the frontend. Read the **repo root `AGENTS.md`** first for the
big picture (prod topology, data-model contract, mobile safe-area rules). This
file only covers FE-local conventions.

## Stack

Vite 6 + React 18 + TypeScript, TanStack Router (file-based) + TanStack Query,
Tailwind, Zustand for auth state, `idb` for the offline outbox, `vite-plugin-pwa`
(Workbox). Forms are plain `useState` + `zod` (the latter for search-param
validation). Charts are hand-rolled inline SVG — **no chart library** (`recharts`
is an unused leftover dependency; don't reach for it). Shared chart geometry lives
in `lib/charts.ts`; the growth page's WHO percentile math and curve geometry live
in `lib/who/`.

## Layout

```

  routeTree.gen.ts    GENERATED by `tsr generate` — never hand-edit

  lib/eventKinds.ts   the ONE event-kind catalog (label, icon, photo alt, open-session, chart series); FeatureKey / RecentEvent / SeriesKey derive from it

  lib/logForm.ts      LogForm shell hook for the /log/* routes: useLogForm (household -> babies -> active baby -> babyId, edit-row lookup from cache, Esc/Cancel -> "/", save/delete + navigate, error state), logSearchSchema, usePrefillOnce, useRestampOnFocus
```

## Route file naming (TanStack file-based routing)

- `__root.tsx` — app shell. Already pads for iOS/Android safe areas; see root
  `AGENTS.md` before adding any `fixed`/`sticky` UI.
- `_app.*` — routes behind the authenticated app layout (`_app.tsx`). E.g.
  `_app.log.bottle.tsx` → `/log/bottle`, `_app.charts.tsx` → `/charts`.
- `_auth.*` — public auth layout (`_auth.login.tsx`, `_auth.register.tsx`).
- `invite.$token.tsx` — dynamic param route.
- After adding/renaming a route file, the route tree regenerates automatically
  (`predev` / `prebuild` / `pretypecheck` run `tsr generate`). If editing
  outside those scripts, run `npm run routes`. Don't edit `routeTree.gen.ts`.

## Data access — the seams that matter

All server I/O goes through `lib/api.ts` and is wired into TanStack Query in
`lib/queries.ts`. Two entrypoints, pick deliberately:

- **`api<T>(path, opts)`** — typed fetch. Attaches the in-memory access token,
  does a single 401→refresh→retry, throws `ApiError` on non-2xx. Use for
  **reads (GET)** and for auth calls.
- **`apiQueued<T>(path, { idempotencyKey, synthesize, … })`** — the **mutation
  seam**. Tries the real request first; on network failure / 5xx / expired-auth
  it enqueues into the offline outbox and returns the caller's `synthesize()`
  result so optimistic cache updates still run. Use for **every write**.

**Log forms.** Each `routes/_app.log.<kind>.tsx` calls `useLogForm` (passing its
create/update/delete hooks and cache `segment`) and renders `<LogFormLayout>`; it
keeps only its fields, validation and the create/update bodies. Photo kinds add
`usePhotoField` + `<PhotoField>`. The per-route quirks that predate the shell are
pinned by `src/test/logRoutes/*.freeze.test.tsx` and surfaced as explicit options
(`errorScope`, `heicPrecheck`, `resetInputOnPick`, `actions`) —
don't "unify" them without a deliberate behavior change.

**Adding a kind also means a row in `lib/eventKinds.ts`** (`EVENT_KIND_ROWS` + `EventKindRows`). `Record<EventKindName, …>` maps (e.g. `RecentRow`'s `BODIES`) then fail to compile until the new kind is handled. Still hand-listed: the Today tiles (`_app.index.tsx`), charts kind lists, `PRESETS`/`SERIES_LABELS` (palette), `mergeRecent`.

**Never bypass the outbox for writes.** A new event kind adds a descriptor
(passed to `defineEventKind` in `lib/queries.ts`) and gets the hooks for free.
The descriptor supplies the URL segment, the create/update bodies, and the
synthesized rows; `lib/eventKind.ts` then, for every write:
1. generates the row id client-side via `makeId()` (`crypto.randomUUID()`),
2. calls `apiQueued` with that id in the body + an `idempotencyKey`
   (create: the row id; PATCH: the row id, or `<id>:patch:<uuid>` while a record
   under the id is already queued; delete: `del-<kind>-<id>`),
3. injects the row via `upsertList` in `onSuccess` so the Today list updates
   immediately, then invalidates to refetch when online.

Photo kinds (diaper, solids, note) reuse the photo helpers + `definePhotoUrl`;
kinds with an in-progress state (nursing, sleep) pass an `open` descriptor and get
`useOpen` (the `/open` query) and `useEnd` (the end mutation).

This works because the BE accepts client ids and does `ON CONFLICT (id) DO
NOTHING`, so replay is idempotent (see `lib/outbox.ts` header for the full
contract). `lib/outbox.ts` is import-cycle-free leaf code — it receives its
dispatcher via `setDispatcher` (wired at the bottom of `api.ts`); don't import
`api` into `outbox`.

## Units & timezones

- DB is canonical `ml` / `cm` / `grams` / UTC. `lib/units.ts` is the **only**
  place canonical values get converted to the user's display unit. Keep new
  formatters there, framework-agnostic (no React/hooks/date-fns), with a
  `units.test.ts` case. Conversion constants are named (`ML_PER_FL_OZ`, etc.).
- List endpoints take RFC3339 `from`/`to`; compute the window in the user's
  timezone on the FE (`date-fns` / `date-fns-tz`), send UTC to the API.

## Auth state

`lib/authStore.ts` (Zustand) holds the in-memory access token only. The
refresh token is NOT stored by JS — the FE and API share an origin (the API
binary embeds the SPA, see `apps/api/internal/spa/`), so the BE keeps the
refresh token in a first-party `httpOnly` cookie. `bootstrapAuth()` runs on
mount and POSTs `/v1/auth/refresh` with `credentials: 'include'`; the browser
supplies the cookie. A first-party cookie survives iOS WebKit ITP eviction,
which `localStorage` did not. On login success, call `kickAfterReauth()` so
outbox records parked on a 401 backoff drain immediately.

## API base URL

`VITE_API_BASE_URL` is left empty in every deploy now — the SPA is served
same-origin (dev via the Vite proxy, prod via the API binary), so requests
hit a relative `/v1`. `api.ts` appends `/v1`. (Set it to an absolute origin
only if you ever split the FE back onto a different host.)

`make web-build` (runs `tsc -b` + `vite build`) and `npm run lint` + `npm run
test` (Vitest, uses `fake-indexeddb` for outbox tests). These match CI; don't
push without them green. Every `lib/*.ts` module ships with a `.test.ts`
sibling — keep that up.
